# 可写寄存器钩子 `debugfs/reg_rw`

> **结论**：`reg_rw` 是驱动提供的"任意偏移 + 任意 32 位值"写入口（`zx279128s-main.c:6004-6026` 的注释），写调用只有 `:6149` 的 `writel`。它把可写范围钉在 `0x354000..0x3540FF`（`:6027-6028`），默认关闭（`:6040`），
> 但**白名单只保护地址，不保护语义**：块内每 4 字节都可以写，包括命令字 `0x354014`、数据口 `0x35401c`、状态位 `0x354018`。
> 写后没有自动回滚（`:6148-6160`）。因此本文的重心不是"怎么用"，而是"什么情况下不能用、出了事怎么退"。

> 本文只做**静态读码 + 手工核对**：未上机、未 ssh、未写任何寄存器。

## §1 定位与物理地址换算

**节点路径**：`/sys/kernel/debug/92000000.ethernet/reg_rw`。

- debugfs 目录名取 `dev_name(adapter->dev)`（`zx279128s-main.c:6184`）；平台设备来自 DTS 节点 `gmac: ethernet@92000000`（`patches-6.18/026-ARM-dts-zte-Add-ZX279128S-SoC-description.patch:220`），所以目录是 `92000000.ethernet`。
- 节点在 `zx_eth_debugfs_init()` 里以 `0644` 创建（`zx279128s-main.c:6236`）；同函数里 `reg_ro` 在 `:6230`。

**偏移口径**：相对驱动 reg base `0x92000000` 的字节偏移。

- DTS：`reg = <0x92000000 0x400000>`（同一 patch `:222`）。
- 驱动：`adapter->base = devm_platform_ioremap_resource(pdev, 0)`（`zx279128s-main.c:6329`）。
- 头文件口径原文："Register offsets from the start of the block (0x92000000)"（`zx279128s-eth.h:37`，注释块 `:36-40`）。

| `reg_rw` 里写的偏移 | 实际物理地址 | 说明 |
|---|---|---|
| `0x354000` | `0x92354000` | TM SCH 块起点，也是 `0x354000` 使能字 |
| `0x354004` | `0x92354004` | 同块内 |
| `0x3540FC` | `0x923540FC` | 白名单内**最后一个** 4 字节对齐地址 |
| `0x354100` | — | 越界，`-EINVAL`（`:6079-6083`） |

换算规则：`物理地址 = 0x92000000 + 偏移`。若手上的寄存器号是相对 `ZX_TM_BASE = 0x340000`（`zx279128s-eth.h:90`）给的，先加 `0x340000` 再写进来；不要加两次。

## §2 用法

```sh
D=/sys/kernel/debug/92000000.ethernet
ARM=/sys/module/zx279128s_eth/parameters/reg_rw_arm

# 1) 先读：用 reg_ro（只读），确认旧值与目标字
echo "0x354000 0x4" > $D/reg_ro
cat $D/reg_ro                # 例：0x354000: 00000042

# 2) arm（默认 0）
echo 1 > $ARM

# 3) 写一个 32 位字：偏移 + 值，两段都接受 0x/十进制
echo "0x354000 0x00000042" > $D/reg_rw

# 4) 读回：只回显“上一次写入 + 该偏移当前值”
cat $D/reg_rw                # last: off=0x354000 val=0x00000042 now=0x00000042

# 5) 查审计（每次成功写一行）
dmesg | grep 'reg_rw:'

# 6) 用完立刻收回 arm
echo 0 > $ARM
```

> 上面写回的 `0x00000042` 只是"把刚读到的值原样写回"的占位示例；实际值必须按 §1 的地址口径自己算出，且先用 `reg_ro` 读回确认旧值。

- 模块参数路径来自驱动自己的提示行（`zx279128s-main.c:6012`、`:6130`）；`main.c` 与 `accel.c` 一起链进 `zx279128s_eth`（`zx279128s-accel.c:6290`）。
- 参数默认 0：`static int reg_rw_arm;`（`:6040`），`module_param(..., 0644)`（`:6041`）。
- `cat` 在从未写过时输出 `reg_rw: no write yet (arm=%d)`（`:6106-6109`）。
- 读路径**不受 arm 限制**（`:6093` 注释，`:6094-6113` 实现）。

## §3 实现事实（逐条带行号）

| 项 | 事实 | 证据 |
|---|---|---|
| 写格式 | 必须**恰好两段** `0x<off> <val>`；少一段、多一段都 `-EINVAL` | `zx279128s-main.c:6046-6073` |
| 数字解析 | `kstrtou32(tok, 0, ...)`：自动识别 `0x` 前缀，十进制亦可；只接受 u32 | `:6060`、`:6066` |
| 输入缓冲 | `char tmp[64]`，`count >= 64` 或 `count == 0` 直接 `-EINVAL` | `:6048`、`:6051-6052`、`:6135-6136` |
| 单次写多少 | **只有一个 32 位字**：`writel(val, base + off)`；没有长度参数、没有批量 | `:6149` |
| 值域 | 接受任意 u32（`0x00000000`–`0xFFFFFFFF`），代码不按位掩码裁剪 | `:6066`、`:6149` |
| 白名单 | 偏移 ∈ `[0x354000, 0x3540FF]`，越界 `-EINVAL` | `:6027-6028`、`:6079-6083` |
| 对齐 | `off & 0x3` 非零即 `-EINVAL`；实际可写 `0x354000, 0x354004, …, 0x3540FC` | `:6085-6088` |
| arm 门 | `if (!READ_ONCE(reg_rw_arm))` 才拒绝 ⇒ **任何非 0 值都算 arm**，不是只认 1 | `:6126-6132` |
| 未 arm 返回 | `-EPERM`；提示 `dev_info` **每次 module load 只打一次** | `:6126-6132`、`:6127-6128` |
| 收回 | 任何时候 `echo 0 > /sys/module/zx279128s_eth/parameters/reg_rw_arm` 即重新关闭；下一次 write 立刻生效 | `:6126` |
| 写前读 | `old = readl(base + off)`，随后 `writel` | `:6148-6149` |
| 写后校验 | **没有**：`writel` 之后不读回、不比对；成功 = 系统调用返回 | `:6149-6160` |
| 审计 | 每次成功写一行 `dev_info`：`reg_rw: off=0x%06x val=0x%08x old=0x%08x` | `:6158-6159` |
| 回显状态 | `have_last/last_off/last_val` 三个文件级 static | `:6030-6033`、`:6151-6155` |
| 锁范围 | `mutex` 只护回显状态；`readl/writel` 在锁外 | `:6100-6104`、`:6148-6155` |
| 返回码 | 成功 `count`；未 arm `-EPERM`；格式/白名单/对齐/长度 `-EINVAL`；`copy_from_user` 失败 `-EFAULT` | `:6160`、`:6132`、`:6083`、`:6088`、`:6165`、`:6138` |
| 权限 | debugfs 文件 `0644`：root 可写，其他只读 | `:6236` |

**并发/原子性（要单独说清）**：

1. `readl`（`:6148`）与 `writel`（`:6149`）都**不在** `zx_reg_rw_lock` 内；锁从 `:6151` 才开始。两个写者并发时，"读旧值→写新值"会交错，`old=` 记录的就不再是"你写之前的值"。
2. 没有 read-modify-write 接口：想只改一个位，必须自己用 `reg_ro` 读全字、在用户态算好、再用 `reg_rw` 写回整字（32 位全宽覆盖）。
3. `zx_reg_rw_warned` 也是普通 `bool`，未加锁（`:6127-6128`）；它只影响提示次数，不影响安全性。

## §4 安全闸（代码里逐条）

写请求依次过：

1. **arm 闸**：`reg_rw_arm == 0` 拒绝，返回 `-EPERM`（`:6126-6132`）。
2. **格式闸**：两段数字，缓冲 <64 字节（`:6046-6073`、`:6135-6136`）。
3. **白名单闸**：`0x354000..0x3540FF`（`:6079-6083`）。
4. **对齐闸**：4 字节（`:6085-6088`）。

**闸不覆盖的东西**（这正是危险来源）：

- 不检查"这个偏移是否只读"：`0x354018` 是 vendor 的只读状态位（`.scratch/ffe-fastpath/cpuport-diff/20261104-2325/logs/TABLES.txt:19`，`type=1`），但它在白名单内，代码照写不误（`:6079-6089` 只看范围与对齐）。
- 不检查"值是否合法"：任何 u32 都放行（`:6066`）。
- 不检查"写的是什么表/索引"：白名单是整个 256 B 块，命令字 `0x354014` 就在块内（`.scratch/ffe-fastpath/cpuport-diff/20261104-2325/logs/TABLES.txt:18`）。

## §5 审计：`dmesg` 是唯一的写入史

每次成功写一行，格式固定（`zx279128s-main.c:6158-6159`）：

```
reg_rw: off=0x354000 val=0x00000042 old=0x00000000
```

- `off/val` 是你这次写的；`old` 是**写前立刻 `readl` 的值**（`:6148`）。
- 没有"写后值"字段；写后实际值要么看 `cat reg_rw` 的 `now=`（`:6111-6112`），要么用 `reg_ro` 重读。
- 建议在任何一次写之前先 `dmesg > /tmp/dmesg-before.txt`：大范围操作会产生上千行 `dev_info`，环形缓冲可能把基线刷掉；出事后 `old=` 是唯一可用来手工回滚的线索。
- `dmesg | grep 'reg_rw:'` 也会命中未 arm 时那行 `reg_rw: disabled (reg_rw_arm=0); ...`（`:6130`）和 usage 行（`:6164`），看 `off=/val=/old=` 三字段才是一次真实写。

## §6 已知危险场景（不是"注意"，是四类会真出事的情况）

> 本节证据目录 `.scratch/ffe-fastpath/cpuport-diff/20261104-2325/logs`（下文简写 `L/`）。

### ① 间接访问：写错表号/索引会打到活着的表

`0x354014` 是 SCH 间接访问的**命令字**（`L/TABLES.txt:18`，地址 `0x92354014`，mask `0x8fcfffff`），原厂把它拼成 `idx | (table << 22) | (读位 << 27)`（`L/tm.objdump.txt:61767-61780`：`cmp r2,#15`、`cmpls r3,#512`、`add r5,r5,r8,lsl #22`）。

- `reg_rw` 的白名单只保证"你能写 `0x354014`"，**不保证你写的表号是安全的**（`:6079-6089` 完全没有表号概念）。
- 写错表号 = 把数据写进另一张正在参与转发的表（队列额度/调度权重这类命名是按我方 `0x344014` 窗口推断的，见 §9，不是 `0x354014` 窗口的直接证据）。这类写**不会报错**：`writel` 后函数直接返回 `count`（`:6149-6160`），错误只在流量上表现出来。
- 结论：没有从原厂反汇编/真机读回确认过 `(table, idx)` 语义之前，不要碰 `0x354014`。

### ② 置位 TM 整形使能位（`0x354000` bit0/bit4）可能立刻断 SSH

- `0x354000` 的位定义：bit0 `que_sharp`、bit1 `dwrr`、bit4 `tcont_sharp`、bit6 `secsch_dwrr`（`docs/reference/debugfs-reg-ro.md:81`）。
- 原厂初始化确实调 `sch_set_que_sharp_enable(1)` 与 `sch_set_tcont_sharp_enable(1)`（`L/VENDOR-SCH-INIT.txt:18-25`），且**先置使能、后填表**（填表循环从 `:32-49` 开始）。也就是说"使能已开、表里还是旧值/零"的窗口在原厂流程里真实存在。
- 后果：使能一置位，全口立刻按表内**当前** `fill_rate/bucket_cap` 限流。表里如果是 0 或未初始化，等于把端口限到接近 0；`L/INDIRECT-TABLES.txt:33` 记录表 14 的索引 0 是 CPU 口，而 SSH 报文进出 SoC 必须经这个口 ⇒ 它被限到 0 时 SSH 当场断连，回滚命令也发不出去。
- 结论：置位前必须先把表填成"等于或大于当前需求"的值，并在**带外通道**（串口/物理重启）可用时做。

### ③ 写后没有自动回滚，兜底只有"手工写回"或"重启"

- 写路径只做 `readl → writel → 记 static → dev_info`（`:6148-6160`），代码里没有任何写回/恢复/定时撤销逻辑。
- 手工写回的前提是 `old=` 准确；并发写会让它失真（见 §3 并发第 1 条）。
- 重启能清掉本次写入（这些是 volatile 寄存器），但**不保证**回到写前快照：重启回到的是复位默认值，与写前值是否相同未验证。
- 结论：每次写之前先想好"这一条怎么退"；退不回来就不要写。

### ④ `0x354014` / `0x35401c` 写 0 的真实语义（别记反）

- `0x354014 = 0`：命令字 → `table 0, idx 0`，**写方向**（读位 bit27 为 0）。这是"选中表 0 的第 0 项"，不是空操作。
- `0x35401c = 0`：这是**数据口**（`L/TABLES.txt:20`），本身不带表号；原厂顺序是"先写命令字 `0x354014`，再写数据 `0x35401c`"（`L/tm.objdump.txt:63652-63661`，表 5）。单独写 `0x35401c` 等于把 0 写进**上一次 `0x354014` 选中的那个表项**。
- 所以危险动作是：不要在没设好命令字时写 `0x35401c`；也不要把 `0x354014` 写 0 当成"清空/复位"。两条都会落到某个真实表项上。

### ⑤ 补充：`0x354018` 状态位在白名单内

`0x354018` 是 vendor 的只读 done 状态（`L/TABLES.txt:19`，mask `0x1`，`type=1`），原厂每次间接写前轮询它、最多 19 次（`L/tm.objdump.txt:63606-63617`）。它落在白名单里，`reg_rw` 不排除（`:6079-6089`）。把它写成 0 或别的值，可能让后续间接访问永远等不到 done。

### ⑥ 补充：并发写会互相踩

见 §3。不要用并行脚本/多终端同时写同一块；一次只发一条，写完 `cat` 确认再发下一条。

## §7 与 `reg_ro` 的分工

| | `reg_ro` | `reg_rw` |
|---|---|---|
| 用途 | 读任意窗口现值 | 写**一个**已确认的字 |
| 范围 | `0x300000..0x3FFFFF`，长度 4..256、4 的倍数 | `0x354000..0x3540FF`，4 字节对齐 |
| 写侧 | 只选范围，不碰寄存器 | 真的 `writel` |
| 读侧 | 每次 `cat` 现场 `readl`，可读任意范围 | 只回显"上一次写 + 该偏移当前值"，不能选范围 |
| 默认闸 | 无（只读） | `reg_rw_arm=0` + `-EPERM` |

证据：`zx279128s-main.c:5855-5858`、`:5900-5925`、`:5946-5949`（`reg_ro`）；`:6027-6028`、`:6093-6113`、`:6126-6132`（`reg_rw`）。

**用法约定**：读一律走 `reg_ro`；`reg_rw` 只用于"已经用 `reg_ro` 读过旧值、已经在离线环境确认过目标值、且写回路径明确"的写。禁止拿 `reg_rw` 当探测工具扫块。

## §9 未核实 / 边界

- `0x354014` 的 bit31 语义未知；原厂 34 个调用点恒写 0（统计与逐点实参见 `.scratch/ffe-fastpath/tm-sch-plan/20261105-0000/RESULT.md:32-38`），保守做法是永远写 0。
- 表号 0/1/4 的语义是按我方 `0x344014` 窗口的命名（`zx279128s-eth.h:112-115`：表 0=队列、1=队列占用、2=RED、4=SCHED）**推断**的，不是 `0x354014` 窗口的直接硬件证据；两个窗口是不同的命令寄存器，编号不能互相套用。
- 本板 `0x354000` 当前值本轮**未实测**；文档不假设它现在是 0 或某个固定值，操作前一律先用 `reg_ro` 读。
- 本文未上机验证任何一次写；`reg_rw` 的实际效果（尤其整形位）需要带外通道保护下的单独一轮实验。
